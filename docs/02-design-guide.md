# 디자인 가이드

## 디자인 콘셉트

이 채팅앱은 밝고 부드러운 감성의 프렌들리 팝 스타일을 지향한다. 사용자가 처음 접했을 때 부담 없이 대화를 시작하고 싶어지는 따뜻한 분위기를 만든다.

핵심 키워드:

- 귀여움
- 밝음
- 부드러움
- 안전함
- 설렘
- 가벼운 대화
- 모바일 친화적

## 전체 분위기

레퍼런스 이미지는 흰색과 연한 크림색 배경 위에 핑크, 코랄, 보라, 민트, 하늘색 포인트를 사용하는 밝은 채팅앱 디자인이다. 전체적으로 둥근 카드, 넓은 여백, 약한 그림자, 귀여운 일러스트 요소를 활용한다.

앱의 첫인상은 데이팅앱처럼 과하게 자극적이지 않고, 친구 추천 채팅앱처럼 편안해야 한다. 수익형 채팅 구조를 가지더라도 화면은 신뢰감 있고 안전하게 보여야 한다.

## 브랜드 방향

임시 브랜드 톤은 ChitChat 같은 가볍고 발랄한 대화 서비스를 기준으로 잡는다. 실제 서비스명은 추후 변경 가능하므로, 디자인 시스템은 특정 이름에 강하게 묶지 않는다.

### 로고 느낌

- 둥근 산세리프 글자
- 핑크와 보라 그라데이션
- 작은 말풍선, 하트, 반짝이 장식 사용 가능
- 너무 성인 채팅앱처럼 보이지 않게 밝고 안전한 느낌 유지

## 타이포그래피

한국어 모바일 앱 기준으로 읽기 쉬운 산세리프를 사용한다.

우선순위:

1. Pretendard
2. system-ui
3. Apple SD Gothic Neo
4. Noto Sans KR
5. sans-serif

권장 크기:

- 화면 제목: 24px / 700
- 섹션 제목: 18px / 700
- 본문: 15px 또는 16px / 400~500
- 보조 텍스트: 13px 또는 14px / 400
- 작은 배지: 11px 또는 12px / 600

## 레이아웃 원칙

### 모바일 우선

첫 구현은 모바일 화면을 기준으로 만든다. 데스크톱에서는 모바일 화면을 확장한 대시보드 형태로 보여준다.

### 여백

- 기본 화면 좌우 여백: 20px
- 카드 내부 여백: 16px~20px
- 섹션 간격: 24px~32px
- 버튼 높이: 48px~56px

### 모서리

- 기본 카드 radius: 20px
- 버튼 radius: 14px~18px
- 프로필 이미지 radius: 원형
- 작은 배지 radius: 999px

### 그림자

과한 그림자는 쓰지 않는다. 카드가 살짝 떠 보이는 정도만 사용한다.

예시:

```css
box-shadow: 0 12px 30px rgba(73, 80, 87, 0.08);
```

## 주요 화면 구성

### 1. 랜딩 화면

목표는 사용자가 앱의 분위기를 바로 이해하고 가입 버튼을 누르게 만드는 것이다.

구성:

- 로고
- 짧은 소개 문구
- 핵심 가치 카드 3개
  - 가벼운 대화
  - 새로운 친구
  - 안전한 환경
- 귀여운 캐릭터 또는 말풍선 일러스트
- 시작하기 버튼

톤:

- 밝고 귀여움
- 수익형 앱 느낌보다 커뮤니티/친구 찾기 느낌
- 신뢰감 있는 설명 포함

### 2. 온보딩 화면

가입 후 사용자가 원하는 대화 스타일을 고르게 한다.

질문 예시:

- 어떤 대화를 원하시나요?
- 편한 수다
- 취미 공유
- 진지한 대화
- 고민 상담

UI:

- 카드형 선택지
- 선택 시 부드러운 핑크 테두리
- 하단 고정 다음 버튼
- 진행 표시 `1 / 3` 형태

### 3. 홈 화면

홈 화면은 추천 친구와 최근 대화로 구성한다.

구성:

- 상단 검색바
- 알림 아이콘
- 내 프로필 썸네일
- 오늘의 추천 친구 카드
- 최근 대화 리스트
- 사이드 또는 하단 내비게이션

데스크톱에서는 좌측 사이드바를 사용할 수 있고, 모바일에서는 하단 탭바를 사용한다.

### 4. 탐색 화면

유저 목록을 카드 또는 리스트로 보여준다.

표시 정보:

- 프로필 이미지
- 닉네임
- 나이
- 지역
- 온라인 상태
- 관심사 태그
- 좋아요 버튼

필터:

- 전체
- 온라인
- 신규
- 내 주변

### 5. 채팅 화면

채팅 화면은 따뜻하고 부담 없는 메신저 느낌으로 만든다.

구성:

- 상단 상대 프로필 영역
- 온라인 상태
- 전화/영상/더보기 아이콘은 추후 기능 전까지 비활성 또는 숨김
- 날짜 구분선
- 상대 메시지: 흰색 말풍선
- 내 메시지: 연핑크 말풍선
- 입력창
- 전송 버튼

주의:

- 유료 메시지 제한이 들어가더라도 채팅 경험이 끊기지 않게 자연스러운 안내 모달을 사용한다.
- 과금 유도 문구는 강압적으로 보이지 않게 작성한다.

### 6. 프로필 화면

프로필은 신뢰와 매력을 동시에 보여줘야 한다.

구성:

- 큰 프로필 이미지
- 닉네임 / 나이 / 지역 / 온라인 상태
- 소개 문구
- 관심사 태그
- 받은 하트 수
- 받은 좋아요 수
- 즐겨찾기 수
- 프로필 편집 버튼
- 포인트 충전 버튼

### 7. 포인트 충전 화면

수익형 앱의 핵심 화면이므로 단순하고 명확해야 한다.

구성:

- 현재 포인트
- 충전 상품 카드
- 추천 상품 강조
- 가격
- 결제 안내 문구

상품 예시:

- 50P
- 120P
- 300P
- 600P
- 1200P

주의:

- 가격과 포인트는 명확히 표시한다.
- 환불/이용 조건 문구를 숨기지 않는다.
- 미성년자/성인 여부 정책은 추후 정책 문서에서 분리 관리한다.

### 8. 알림 화면

알림은 탭으로 나눈다.

탭:

- 전체
- 좋아요
- 대화
- 시스템

알림 유형:

- 좋아요를 받음
- 메시지를 받음
- 운영팀 공지
- 포인트 사용 안내

### 9. 컴포넌트 가이드 화면

개발 중 UI 일관성을 확인할 수 있도록 컴포넌트 샘플 화면을 둔다.

포함:

- 기본 버튼
- 보조 버튼
- 비활성 버튼
- 아이콘 버튼
- 상태 표시
- 배지
- 입력 필드
- 카드

## 컴포넌트 규칙

### Button

종류:

- Primary Button
- Secondary Button
- Disabled Button
- Icon Button

Primary Button:

```css
background: linear-gradient(135deg, #FF6B9D, #FF8E53);
color: #FFFFFF;
border-radius: 16px;
height: 52px;
font-weight: 700;
```

Secondary Button:

```css
background: #FFFFFF;
color: #FF6B9D;
border: 1px solid #FFB6D0;
border-radius: 16px;
height: 52px;
```

### Card

```css
background: #FFFFFF;
border: 1px solid #F1F3F5;
border-radius: 20px;
box-shadow: 0 12px 30px rgba(73, 80, 87, 0.08);
```

### Input

```css
background: #FFFFFF;
border: 1px solid #F1F3F5;
border-radius: 999px;
height: 44px;
padding: 0 16px;
```

### Badge

배지는 작은 상태 정보에 사용한다.

예시:

- 온라인
- NEW
- 12
- 추천

```css
border-radius: 999px;
padding: 4px 8px;
font-size: 12px;
font-weight: 700;
```

## 일러스트/장식 요소

앱 곳곳에 작은 장식 요소를 사용할 수 있다.

사용 가능:

- 하트
- 별
- 반짝이
- 말풍선
- 작은 동물 캐릭터
- 둥근 젤리 형태 오브젝트

주의:

- 채팅이나 결제 버튼 주변에 과하게 넣지 않는다.
- 기능 이해를 방해하지 않는다.
- 화면당 장식은 2~4개 정도로 제한한다.

## 수익형 UX 원칙

수익형 채팅앱이지만 사용자가 불쾌하게 느끼지 않게 설계한다.

원칙:

- 결제 전 무료 경험을 제공한다.
- 포인트 차감 조건을 명확히 보여준다.
- 메시지 전송 제한은 갑작스럽게 막지 않는다.
- 충전 유도는 밝고 부드럽게 표현한다.
- 신고/차단은 항상 접근 가능해야 한다.

## 접근성 원칙

- 작은 회색 텍스트를 너무 연하게 쓰지 않는다.
- 주요 버튼 대비를 충분히 확보한다.
- 터치 영역은 최소 44px 이상으로 만든다.
- 아이콘만 있는 버튼에는 aria-label을 제공한다.
- 색상만으로 상태를 구분하지 않는다.

## 개발 적용 원칙

디자인 구현 시 다음 구조를 따른다.

```txt
apps/web/src/
 ├─ app/
 ├─ features/
 │   ├─ landing/
 │   ├─ onboarding/
 │   ├─ home/
 │   ├─ explore/
 │   ├─ chat/
 │   ├─ profile/
 │   ├─ billing/
 │   └─ notifications/
 └─ shared/
     ├─ components/
     ├─ styles/
     └─ constants/
```

스타일 상수는 `shared/constants` 또는 `shared/styles`에 분리한다. 각 화면은 자기 feature 폴더 안에서 관리하고, 공통 컴포넌트만 shared로 올린다.

## 첫 구현 우선순위

1. 디자인 토큰 정리
2. 공통 Button / Card / Badge / Avatar 컴포넌트
3. 랜딩 화면
4. 온보딩 화면
5. 홈 화면 목업
6. 채팅 화면 목업
7. 포인트 충전 화면 목업

실제 데이터 연동은 UI 목업이 안정된 뒤 붙인다.
