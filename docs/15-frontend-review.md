# 프론트엔드 점검 결과

마지막 갱신: 2026-06-25

## 점검 범위

- 앱 진입과 인증 세션
- 가입과 프로필 저장
- 토크 작성·삭제와 직접대화 시작
- 채팅방 목록·메시지·신고·차단
- 포인트 조회와 보상 버튼
- 마이룸 불러오기·저장·캔버스 조작
- 프로필 사진 크롭과 업로드
- 회원 탈퇴
- 관리자 신고 처리·정지·콘텐츠 삭제
- 모바일 접근성, 오류 복구, React 상태 관리
- Vite 빌드와 GitHub Actions 계약

- 토크 등록 실패 시 작성 중인 문장 보존

- 직접대화 시작 잠금을 state와 ref로 이중화
- 읽지 않은 메시지 수만 새 채팅 표시 기준으로 사용
- 채팅 목록 오류 재시도와 방 나가기 중복 실행 방지
- 메시지 전송 실패 후 입력값 유지
- 채팅 신고·차단 중복 실행 방지와 차단 확인 단계 추가
- 사진 크롭 실패 후 버튼이 멈추는 문제 수정
- 포인트 요청 실패 후 출석·광고 버튼이 멈추는 문제 수정
- 포인트 갱신 실패 시 기존 잔액 유지
- 프로필 입력값과 localStorage 프로필 값 정규화
- 마이룸 로딩 실패를 기본 방과 구분
- 마이룸 로딩 실패 시 편집 메뉴와 저장 버튼 비활성화
- 채팅 화면의 원격 마이룸 로딩 실패 안전 처리
- 마이룸 가구 키보드 선택과 화살표 이동 지원
- 마이룸 드래그 애니메이션 프레임 정리
- 차단 목록 로딩 오류와 해제 중복 실행 처리
- 최상위 React 오류 경계 추가
- 설정 하위 화면 lazy loading과 `Suspense` 적용
- 공통 `Modal`의 ESC, 배경 클릭, 스크롤 잠금, 포커스 복원, Tab 순환 적용
- 공통 `usePollingTask`로 토크·채팅방·메시지·최근 사용자 갱신 통합
- 문서가 숨겨졌을 때 폴링 중지와 화면 복귀 시 즉시 갱신
- 회원 탈퇴 확인창, 실패 복구, 로컬 상태 초기화 적용
- 관리자 신고 상태·메모·정지 기간 처리 UI 적용
- 관리자 정지 해제 UI 연결
- 관리자 토크 삭제와 채팅 메시지 삭제 처리 UI 적용
- 관리자 처리 성공 안내가 새로고침에 사라지지 않도록 수정
- 전체 신고 필터에서 새 응답 기준으로 카드 폼 상태 동기화
- 관리자 처리·정지 해제·콘텐츠 삭제 중복 실행 방지
- 공통 훅 외 직접 `setInterval` 사용을 CI 계약 검사로 차단
- Playwright 기반 `Web E2E` workflow 추가
- E2E를 production build와 preview 서버 기준으로 실행
- 실패 시 HTML report, trace, 스크린샷, 영상 artifact 보관

## 자동 회귀 테스트 현황

현재 **15개 Playwright 테스트 케이스**가 다음 사용자 흐름을 검증합니다.

- 신규 가입 저장 실패
- 신규 가입 저장 성공
- 토크 작성 실패 후 초안 보존
- ESC로 모달 닫기와 이전 포커스 복원
- 쪽지 연속 클릭 시 채팅방 생성 요청 1회
- 메시지 전송 실패 후 입력 내용 보존
- 채팅방 나가기 취소
- 채팅방 나가기 실패
- 채팅방 나가기 성공
- 회원 탈퇴 실패와 재시도 버튼 복구
- 회원 탈퇴 성공과 로컬 계정 상태 삭제
- 프로필 저장 실패와 기존 프로필 보존
- 프로필 사진 업로드 실패와 프로필 저장 차단
- 포인트 보상 실패와 버튼 복구
- 마이룸 로드 실패 후 편집·저장 차단

회원 탈퇴와 설정 복원력 테스트는 Bearer 인증 헤더도 함께 검사합니다.

## 이번 전체 점검에서 수정한 프론트엔드 문제

- 신고 처리 성공 메시지가 목록 갱신 과정에서 즉시 사라지던 문제
- 처리 후 동일 신고 카드가 이전 status·admin note를 유지하던 문제
- 정지 해제 API가 UI에 연결되지 않았던 문제
- 다른 콘텐츠 삭제 중에도 삭제 버튼이 눌릴 수 있던 문제

## 남은 구조 개선

- 관리자 신고 처리·정지·정지 해제·콘텐츠 삭제 전용 E2E 추가
- Android 뒤로가기와 모달 닫기 실기기 회귀
- 실제 Pages/D1/R2 환경에서 회원 탈퇴와 관리자 콘텐츠 삭제 확인
- 운영 오류 수집과 사용자 행동 지표 도입 여부 결정
- 정식 계정 로그인·복구 흐름 설계

## 검증 참고

- `Web Verify` workflow는 `pnpm verify`를 실행합니다.
- `Web E2E` workflow는 `main` push와 pull request에서 Playwright Chromium 테스트를 자동 실행합니다.
- 실제 Cloudflare 환경변수, D1 데이터, R2 업로드·삭제, Android 실기기 동작은 별도 smoke workflow와 실기기 검증이 필요합니다.
- 이번 점검 이후 새 GitHub Actions 결과는 아직 확인되지 않았으므로 통과 상태를 확정하지 않습니다.
