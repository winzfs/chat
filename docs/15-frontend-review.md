# 프론트엔드 점검 결과

마지막 갱신: 2026-06-24

## 점검 범위

- 앱 진입과 인증 세션
- 가입과 프로필 저장
- 토크 작성·삭제와 직접대화 시작
- 채팅방 목록·메시지·신고·차단
- 포인트 조회와 보상 버튼
- 마이룸 불러오기·저장·캔버스 조작
- 프로필 사진 크롭과 업로드
- 모바일 접근성, 오류 복구, React 상태 관리
- Vite 빌드 설정

## 반영 완료

- Vite React 플러그인 활성화
- 가입 정보를 서버에 저장한 뒤에만 가입 완료 처리
- 가입 중 중복 제출 방지와 나이 범위 검증
- 토크 등록 실패 시 작성 중인 문장 보존
- 토크 등록 중 중복 요청 방지
- 상대 `profile_id`가 없는 직접대화 요청 차단
- 내 토크 프로필에서 채팅 시작 버튼 숨김
- 읽지 않은 메시지 수만 새 채팅 표시 기준으로 사용
- 채팅 목록 오류 재시도와 방 나가기 중복 실행 방지
- 채팅 신고·차단 중복 실행 방지와 차단 확인 단계 추가
- 사진 크롭 실패 후 버튼이 멈추는 문제 수정
- 포인트 요청 실패 후 출석·광고 버튼이 멈추는 문제 수정
- 포인트 갱신 실패 시 기존 잔액 유지
- 프로필 입력값과 localStorage 프로필 값 정규화
- 마이룸 로딩 실패를 기본 방과 구분
- 마이룸 로딩 실패 뒤 기본 방으로 기존 방을 덮어쓰지 못하도록 차단
- 채팅 화면의 원격 마이룸 로딩 실패 안전 처리
- 마이룸 가구 키보드 선택과 화살표 이동 지원
- 마이룸 드래그 애니메이션 프레임 정리
- 차단 목록 로딩 오류와 해제 중복 실행 처리
- 최상위 React 오류 경계 추가
- `MyRoomSettingsPanel`을 조립 화면, `useMyRoomEditor` 상태 훅, `MyRoomEditorPanel` 메뉴 UI로 분리
- 마이룸 상태 updater 내부의 다른 상태 setter 호출 제거
- 마이룸 로딩 실패 시 편집 메뉴와 저장 버튼 비활성화
- 마이룸·차단 관리·신고 관리 화면을 `React.lazy`와 `Suspense`로 지연 로딩
- 설정 하위 화면 boolean 상태를 단일 `activeSubpanel` 상태로 통합
- 공통 `Modal` 컴포넌트 추가
- 모달 포털 렌더링, ESC 닫기, 배경 클릭 닫기, body 스크롤 잠금, 이전 포커스 복원, Tab 포커스 순환 통합
- 토크 작성, 프로필 미리보기, 사진 크롭, 채팅 기록, 채팅방 나가기 확인에 공통 모달 적용
- 처리 중인 토크 등록·사진 적용·채팅방 나가기에서는 모달 닫기 방지
- 토크, 채팅방 목록, 채팅 메시지, 최근 사용자 갱신을 공통 `usePollingTask` 훅으로 통합
- 문서가 숨겨졌을 때 폴링 중지, 화면 복귀 시 즉시 갱신, 중복 요청 방지 적용
- 채팅방 내부에서는 채팅방 목록 폴링 중지
- 토크 작성 모달이 열린 동안 토크 목록 폴링 중지
- 공통 훅 외 직접 `setInterval` 사용을 CI 계약 검사로 차단
- Playwright 기반 `Web E2E` workflow 추가
- E2E를 프로덕션 빌드와 preview 서버 기준으로 실행
- 실패 시 HTML report, trace, 스크린샷, 영상을 artifact로 보관
- 모달을 닫은 뒤 원래 버튼으로 포커스를 안정적으로 복원하도록 수정
- 직접대화 시작 잠금을 state와 ref로 이중화해 같은 이벤트 루프의 연속 클릭도 차단

## 자동 회귀 테스트 현황

현재 다음 9개 핵심 사용자 흐름을 브라우저 E2E로 자동 검증합니다.

- 신규 가입 저장 실패 시 가입 화면 유지
- 신규 가입 저장 성공 후 홈 화면 진입
- 토크 작성 실패 후 초안 보존
- ESC로 모달 닫기와 이전 버튼 포커스 복원
- 쪽지 버튼 연속 클릭 시 채팅방 생성 요청 1회 유지
- 메시지 전송 실패 후 입력 내용 보존과 보내기 버튼 복구
- 채팅방 나가기 취소 시 요청 없이 방 유지
- 채팅방 나가기 실패 시 방·확인창 유지와 버튼 복구
- 채팅방 나가기 성공 시 확인창과 방 카드 제거

## 남은 구조 개선

다음 흐름은 후속 E2E 확장이 필요합니다.

- 프로필 사진 크롭 실패·업로드 실패
- 마이룸 로딩 실패 후 저장 차단
- 출석·광고 요청 실패 후 버튼 복구
- Android 뒤로가기와 모달 닫기 실기기 회귀

## 검증 참고

- `Web Verify` workflow는 `pnpm verify`를 실행합니다.
- `Web E2E` workflow는 `main` push와 pull request에서 Playwright Chromium 테스트를 자동 실행합니다.
- 2026-06-24 기준 현재 등록된 E2E 9개 흐름은 GitHub Actions에서 통과했습니다.
- 실제 Cloudflare 환경변수, D1 데이터, R2 업로드, Android 실기기 동작은 별도 smoke workflow와 실기기 검증이 필요합니다.
