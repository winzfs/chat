# 웹 E2E 자동 회귀 테스트

마지막 갱신: 2026-06-25

## 실행 방법

최초 한 번 Chromium을 설치합니다.

```bash
pnpm exec playwright install chromium
```

헤드리스 테스트:

```bash
pnpm e2e
```

브라우저 화면을 보면서 실행:

```bash
pnpm e2e:headed
```

실패 리포트 확인:

```bash
pnpm e2e:report
```

## 현재 자동화된 테스트 15개

### 가입·토크·모달

1. 가입 서버 저장 실패 시 가입 화면 유지
2. 가입 서버 저장 성공 후 홈 화면 진입
3. 토크 등록 실패 시 작성 초안 유지
4. ESC로 모달을 닫은 뒤 이전 버튼으로 포커스 복원

### 직접대화·메시지·채팅방

5. 쪽지 버튼을 같은 이벤트 루프에서 연속 클릭해도 채팅방 생성 요청 1회
6. 메시지 전송 실패 시 입력값 유지와 보내기 버튼 복구
7. 채팅방 나가기 취소 시 서버 요청 없이 방 유지
8. 채팅방 나가기 실패 시 방·확인창 유지와 버튼 복구
9. 채팅방 나가기 성공 시 확인창과 방 카드 제거

### 회원 탈퇴

10. 회원 탈퇴 실패 시 확인창 유지와 재시도 버튼 복구
11. 회원 탈퇴 성공 시 `chitchat.*` 로컬 계정 상태 삭제와 가입 화면 복귀

회원 탈퇴 성공 테스트는 DELETE 요청에 서명 세션 Bearer 인증 헤더가 첨부되는지도 확인합니다.

### 설정 복원력

12. 프로필 저장 실패 시 서버 오류 표시와 기존 프로필 보존
13. 프로필 사진 업로드 실패 시 오류 표시와 프로필 저장 요청 차단
14. 포인트 보상 실패 시 실패 메시지 표시와 버튼 복구
15. 마이룸 로드 실패 시 편집·저장 차단

설정 복원력 테스트는 주요 API 요청의 Bearer 인증 헤더도 확인합니다.

## 아직 추가할 E2E

- 관리자 신고 상태·메모 저장
- 1일·7일·30일·무기한 사용자 정지
- 사용자 정지 해제
- 관리자 토크 삭제
- 관리자 이미지 메시지 삭제와 R2 원본 제거
- 실제 Android 뒤로가기와 모달 닫기

관리자 E2E는 mock UI 검증뿐 아니라 서버 권한과 상태 변경 계약을 함께 확인하도록 구성해야 합니다.

## Mock API 원칙

테스트는 실제 브라우저에서 production build를 실행하지만 API 응답은 `e2e/helpers/mockRoutes.ts`에서 고정합니다. 외부 Cloudflare 환경과 무관하게 화면 상태와 사용자 흐름을 재현합니다.

- 성공·실패 응답을 시나리오별로 명시
- 상태 변경 후 다음 폴링 응답에도 결과 유지
- CSS 클래스보다 role, label, button name 사용
- 실패 시 입력값과 버튼 복구 확인
- 같은 이벤트 루프의 연속 클릭으로 경쟁 조건 재현
- 주요 인증 API의 Authorization 헤더 확인

## CI

`.github/workflows/web-e2e.yml`은 다음 시점에 Chromium 테스트를 실행합니다.

- `main` push
- pull request
- 수동 실행

같은 ref의 오래된 중복 실행은 자동 취소됩니다. 실패 시 다음 파일을 7일 동안 artifact로 보관하고, Playwright report가 생성되지 않으면 workflow를 실패 처리합니다.

- Playwright HTML report
- trace
- 실패 스크린샷
- 실패 영상

## 검증 상태

이번 전체 코드 점검 이후 새 커밋이 추가됐으므로, 기존 과거 통과 결과를 현재 HEAD의 통과로 간주하지 않습니다. 최신 Web Verify와 Web E2E 결과를 확인한 뒤 문서의 검증 상태를 갱신합니다.
