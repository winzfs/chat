# 2026-07-10 프로젝트 강화 작업

## 반영한 변경

### 모바일 회귀 테스트

- 기존 Desktop Chrome 프로젝트 이름을 `desktop-chromium`으로 명확히 변경했습니다.
- Pixel 7 프로필을 사용하는 `mobile-chromium` Playwright 프로젝트를 추가했습니다.
- 동일한 15개 사용자 흐름을 데스크톱과 모바일 뷰포트에서 각각 실행합니다.
- 테스트 실행량 증가를 고려해 Web E2E workflow 제한 시간을 15분에서 25분으로 조정했습니다.

이 테스트는 모바일 레이아웃과 터치 환경에 가까운 브라우저 동작을 확인하지만 Capacitor Android WebView와 실제 소프트 키보드, 시스템 뒤로가기를 완전히 재현하지는 않습니다.

### 런타임 범위

- 루트 `package.json`의 Node 지원 범위를 `>=22.0.0 <23.0.0`으로 고정했습니다.
- 문서의 런타임 표현도 `Node 22.x`로 통일했습니다.
- GitHub Actions와 로컬 지원 범위가 다르게 해석되는 문제를 줄였습니다.

### 문서 상태 표현

- README에 구현 완료, 자동 검증, Preview 검증, Production 검증, 실기기 검증의 차이를 추가했습니다.
- 구현된 로직을 Production 검증 완료로 오해하지 않도록 표현을 수정했습니다.
- 현재 상태를 모바일 웹 MVP와 Android 비공개 테스트 준비 단계로 명시했습니다.

## 이번 변경에서 의도적으로 제외한 항목

아래 항목은 저장소 코드만 수정해서 완료했다고 선언할 수 없습니다.

- Preview와 Production D1 migration 적용
- 실제 D1 데이터 백업과 복원 확인
- Pages Auth/API Smoke 실행
- 실제 R2 객체를 포함한 회원 탈퇴 회귀
- 관리자 정지·해제·콘텐츠 삭제 운영 환경 회귀
- Release AAB 서명과 Android 실기기 설치
- 개인정보처리방침·이용약관의 실제 사업자 정보 확정
- Google Play Data Safety와 콘텐츠 등급 제출

## 다음 코드 작업 우선순위

### P0

1. 이번 브랜치의 Web Verify와 Web E2E 결과 확인
2. 모바일 E2E에서 발견되는 고정폭·오버플로·모달 문제 수정
3. 관리자 API 권한, 직접대화 포인트 차감, 탈퇴·정지 토큰 차단에 대한 API 통합 테스트 추가

### P1

1. 런타임 DDL을 migration으로 완전히 이전
2. R2 삭제와 D1 상태 변경 사이의 실패를 재시도할 수 있는 삭제 작업 상태 도입
3. 관리자 신고 처리·정지·정지 해제·콘텐츠 삭제 전용 E2E 추가
4. Android 뒤로가기, 소프트 키보드, safe area 실기기 회귀

### P2

1. 계정 복구 가능한 이메일 또는 소셜 로그인 도입
2. 오류 수집과 장애 알림 도입
3. 폴링 부하 측정과 증분 조회 또는 실시간 구조 검토
4. 문서 중복을 줄이고 구현 상태 문서를 단일 원본으로 운영

## 출시 판단 원칙

GitHub Actions workflow가 존재하거나 코드에 보호 로직이 있다는 사실만으로 출시 준비 완료로 판단하지 않습니다. 현재 HEAD의 자동 검증 결과와 Preview·Production·Android 실기기 결과를 함께 확인한 뒤 출시 후보로 표시합니다.
